## 1. 背景与目标

《面向对象程序设计课程设计》这类课程的传统流程是：教师线下布置题目 → 学生各自开发 → 交源码与报告 → 教师逐个翻代码、听答辩、算分。存在三个痛点：

1. **选题靠抢、人数靠数**：并发选题容易超卖，人工核对名单成本高；
2. **评审靠人看**：几十份源码与报告无法逐一细读，反馈滞后且标准不一致；
3. **分数靠 Excel**：答辩、源码、报告三部分加权容易算错，调整过程不留痕。

本系统把这条链路产品化，目标：

- **一个系统跑完全流程**：选题 → 提交 → 评审 → 答辩 → 评分 → 发布 → 通知；
- **每个动作可追溯**：审核日志、调整原因、任务记录、`traceId` 贯穿日志；
- **AI 做初评、教师做决策**：AI 给出分数与问题清单，教师保留最终调整权；
- **并发安全**：名额预占靠数据库原子操作 + 唯一索引，不依赖前端约束。

## 2. 角色与权限

| 角色 | 代码 | 核心诉求 | 权限边界 |
|---|---|---|---|
| 学生 | `STUDENT` | 选到合适的题、按时交材料、看到评审与成绩 | 只能操作自己的选题与提交物；成绩仅在教师发布后可见 |
| 教师 | `TEACHER` | 开课出题、管名单、看进度、调分发布 | 只能操作自己创建的开课（`teacherId` 归属校验） |
| 管理员 | `ADMIN` | 账号与系统运维 | 当前无 `/admin/**` 业务端点，主要用于数据核查 |

权限三层校验：

1. **URL 层**：`/api/v1/teacher/**` 需 `TEACHER`，`/api/v1/student/**` 需 `STUDENT`；
2. **数据层**：Service 内校验开课归属、选题归属、文件归属；
3. **业务层**：状态机约束（如只有 `DRAFT` 能发布、只有 `AUTO/ADJUSTED` 能锁定）。

## 3. 业务流程与状态机

```
教师：建课程模板 → 建开课(草稿) → 加学生 → 出题 → 发布开课 → 回收材料 → 重算成绩 → 调整 → 发布
学生：看开课 → 选题 → 上传源码 zip + 报告 pdf → 等待 AI 评审 → 答辩 → 查成绩
```

| 对象 | 状态流转 |
|---|---|
| 开课 `offering` | `DRAFT` →(发布)→ `PUBLISHED` →(关闭)→ `CLOSED` →(归档)→ `ARCHIVED`；`PUBLISHED` 可直接归档 |
| 题目 `topic` | `DRAFT` →(发布)→ `PUBLISHED` →(归档)→ `ARCHIVED` |
| 选题 `selection` | `SELECTED` → `SUBMITTED` → `DEFENDING` → `DEFENDED` → `GRADED`；`SELECTED` 可 `CANCELED`（名额释放） |
| 提交物 `submission` | `UPLOADED` → `PARSING` → `VALID` → `ANALYZING` → `ANALYZED`；解析失败转 `INVALID` |
| 异步任务 `async_task` | `PENDING` → `RUNNING` → `SUCCEEDED` / `FAILED`；可 `CANCELED` |
| 成绩 `grade` | `AUTO` →(调整)→ `ADJUSTED` →(发布)→ `LOCKED`；`LOCKED` 可解锁回 `AUTO/ADJUSTED` |
| 答辩 `defense_session` | `CREATED` → `GENERATING` → `READY` → `IN_PROGRESS` → `COMPLETED` → `EVALUATED` |

**算分规则**：`综合分 = (答辩×w_defense + 源码×w_code + 报告×w_report) / 100`，三项权重之和必须为 100；等级 ≥90 优秀、≥80 良好、≥70 中等、≥60 及格、其余不及格。源码/报告分取 `status = SUCCEEDED` 的评审记录的平均值，分母是**有效评审数**。

## 4. 功能需求

> 编号规则：`FR-模块-序号`。「现状」列：✅ 已实现 / ⚠️ 部分实现 / 🚧 规划中。

### 4.1 认证与会话

| 编号 | 需求 | 验收标准 | 现状 |
|---|---|---|---|
| FR-AUTH-01 | 学号/工号 + 密码登录，返回 `accessToken` / `refreshToken` / 用户信息 | 正确凭据返回 `code=0`；错误密码返回 40102 | ✅ |
| FR-AUTH-02 | 无状态 JWT 鉴权，`Authorization: Bearer <token>` | 缺令牌访问受保护接口返回 401 + 统一 `Result` | ✅ |
| FR-AUTH-03 | 访问令牌 2h、刷新令牌 7d；刷新时 Redis 原子消费 jti 防重放 | 旧 refreshToken 二次使用失败 | ✅ |
| FR-AUTH-04 | 改密后所有旧令牌立即失效（令牌版本号机制） | 改密后旧 accessToken 401 | ✅ |
| FR-AUTH-05 | 登录失败限流（用户名维度，1 分钟 5 次） | 第 6 次返回 42901 | ✅ |
| FR-AUTH-06 | 前端 401 自动刷新一次，失败回登录页并保留 `redirect` | 令牌过期后无感续期或跳登录 | ✅ |

### 5.2 设计规范

- **主题**：浅色为默认，支持深色（`data-theme="dark"` + CSS 变量），选择存本地；
- **色板**：品牌靛蓝 `#4f46e5` + 青色强调 `#0891b2`；语义色 ok/warn/danger/info 各配 soft 背景；
- **字体**：系统字体栈（Inter / PingFang SC / Microsoft YaHei），数字使用等宽数位（`tabular-nums`）；
- **圆角与阴影**：卡片 18px、控件 10px、胶囊 999px；三级阴影；
- **组件**：按钮（primary/soft/ghost/danger/icon）、输入、表格、状态胶囊、页签、抽屉、弹窗、Toast、骨架屏、空状态、分页、进度环、步骤条、下拉菜单、命令面板；
- **状态色语义**：草稿/待处理→warn，进行中→info，成功/已发布→ok，失败/已失效→danger；
- **响应式**：≥1180px 四列 KPI，900px 以下折叠侧边栏为抽屉、隐藏面包屑；420px 验证可用；
- **可访问性**：交互元素有 `title`/`aria-label`，弹窗 `role="dialog"` + Esc 关闭，`prefers-reduced-motion` 关闭动画。

### 5.3 交互约定

- 所有破坏性操作走确认弹窗（退选、删除题目、发布成绩、重置密码等）；
- 所有异步结果用 Toast 反馈，并带上后端 `traceId` 前 12 位便于排查；
- 列表空态给出「下一步该做什么」的入口按钮；
- 加载态使用骨架屏，避免布局跳动；
- `Ctrl/Cmd + K` 打开命令面板，可跳转任意有权限的页面、切换主题、打开 Swagger。
