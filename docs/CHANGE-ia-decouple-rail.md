# 架构级解耦：图标轨道 + 教师端 / 学生端独立信息架构

> 本轮目标不是「再调一次间距」，而是解决**两端业务混装**：教师端与学生端此前共用同一套
> 导航表、同一个首页、同一个成绩页，靠页内 `isTeacher` 分叉拼装，导致两端都像「半个后台」。
>
> 三条底线（自始至终未破）：
> 1. 背景色 / 底色 / 品牌色 / 语义色**零新增、零修改**；
> 2. 已实现的业务功能**零改动**（接口、参数、状态机、权限判断、表单校验一个没动）；
> 3. 路由路径与守卫**零改动**，深链、刷新、前进后退行为不变。

## 一、参考对象：PTA 到底好在哪

从 8 张 PTA 截图里提炼出的 7 条可迁移特征：

| # | PTA 的做法 | 为什么「一眼清晰」 | 本项目的落点 |
|---|---|---|---|
| 1 | 左侧**窄图标轨道**（约 72px，图标 + 两字） | 一级入口永远在原地，图标可肌肉记忆；把横向空间全让给内容 | `--sidebar-w` 244px → 76px，深色底保留 |
| 2 | 顶栏**极简**（品牌 + 少量入口），页面标题下放到内容区 | 标题只出现一次，不与导航抢注意力 | 去掉顶栏重复大标题，`--topbar-h` 52px |
| 3 | 页内**二级 tab 横向平铺**（学生名单 / 账号绑定 / 导出 / 设置） | 同一对象的多个视图切换成本最低 | 工作台 `WorkspaceNav` 分组 tab（已有，保留） |
| 4 | **行列表**优于卡片网格（图标 + 标题 + 灰副标题 + 右状态） | 纵向扫读效率高，信息层级靠字号与灰度，不靠边框 | 教学班列表由 7 列表格改为行列表 |
| 5 | 详情页**右侧辅助栏**（登录说明 / 课程 / 授权题目集） | 主区只放主任务，旁支信息不打断主线 | 首页「待办 / 通知 / 流程」右栏（已有，强化） |
| 6 | **筛选条平铺**（类型 / 状态 / 排序 / 搜索同一行） | 不用展开就知道能筛什么 | `ToolbarBar` + tab 平铺（已有） |
| 7 | 标题区含**状态徽章与创建者** | 「这是什么、什么状态、归谁」在首屏一次说清 | `PageHeader` 的 `#meta` 插槽（已有） |

## 三、解耦清单

### 3.1 导航：一张表 → 三棵树

**改造前**：`NAV_GROUPS` 是一张全局表，每条目带 `roles: ['TEACHER','STUDENT']`，运行时过滤。
问题是两端的差异只能靠「加 roles、改 group 双写」表达，条目实际仍绑在一起。

**改造后**：`TEACHER_NAV` / `STUDENT_NAV` / `ADMIN_NAV` 三棵独立树，条目归属由所在树决定。

```js
export const TEACHER_NAV = [
  { group: '教学', items: [{ to: '/', label: '概览' }, { to: '/offerings', label: '教学班' }] },
  { group: '学业', items: [{ to: '/grades', label: '成绩' }] },
  { group: '协作', items: [{ to: '/tasks', label: '任务' }, { to: '/notifications', label: '通知' }] },
  { group: '个人', items: [{ to: '/settings', label: '设置' }] },
]
// STUDENT_NAV 同结构，但「学习」组是 概览 / 我的课程 / 我的选题
```

`navGroupsForRole()` 与 `navItemsForRole()` 的签名和返回结构保持不变，命令面板无需改动。

### 3.2 首页：一个文件两种业务 → 两个文件

`DashboardView.vue`（原 564 行、16 处 `isTeacher` 分叉）拆为：

| 文件 | 职责 | 首屏回答的问题 |
|---|---|---|
| `views/DashboardView.vue` | 10 行薄壳，按角色选组件 | — |
| `views/home/TeacherHome.vue` | KPI、教学班行列表、运行情况（提交率/平均分/权重/成绩分布/高频问题）、待办、通知、教学流程 | 我在教什么、要做什么、能去哪 |
| `views/home/StudentHome.vue` | 六步动线条、**「下一步」引导卡**、材料与评审进度、我的课程、待办、截止提醒 | 现在该做什么、什么时候截止、点哪里 |

学生端新增的「下一步」卡是整页唯一强引导，文案按当前状态推导
（无选题 → 先挑题 / 缺材料 → 上传具体那份 / 材料齐 → 等评审 / 已出分 → 看成绩），
只做展示推导，不改任何路由与状态机。

### 3.3 成绩：一个文件两种业务 → 两个文件

| 文件 | 职责 |
|---|---|
| `views/GradesView.vue` | 薄壳 |
| `views/grades/TeacherGrades.vue` | 选教学班 → 重算 / 调整 / 发布（复用 `GradesTab`） |
| `views/grades/StudentGrades.vue` | 只读成绩卡：综合分 + 三项权重条 + 分项明细 + 教师评语 |

### 3.4 列表形态

教学班列表：7 列表格 → 行列表。学生数 / 题目数 / 已选数 / 学期并入副标题，
整行可点进工作台，右侧操作组 `@click.stop` 不触发跳转。所有按钮（工作台 / 发布 / 关闭 / 归档）
与 `act()` 绑定原样保留。

## 六、未做项与原因

1. **答辩页（`DefenseView.vue`，2359 行、31 处角色分叉）未拆分**。
   它是「同一场答辩会话的两个视角」，共享一套录音、摄像头、心跳、在场检测、违规计数与轮询。
   强行拆成两个页面会导致上述运行时状态重复实现或跨组件传递，回归风险远大于收益。
   已在入口层解耦（教师从教学班进、学生从我的选题进，面包屑与步骤条各走各的）。
2. **工作台右侧辅助栏未加**。8 个 tab 内部都是满宽表格 + 工具栏，塞右栏会把主区压到 900px 以下，
   与「让内容更宽」的目标相反。留作后续按 tab 单独评估。
3. **窄屏二级导航仍是换行 + 横向滚动**，未做下拉折叠。功能不丢，视觉上不如 PTA 紧凑。
4. **实机视觉走查未做**：后端与 AI 服务未启动，`无控制台报错 / 无溢出 / 两分辨率截图对比`
   三条目前只有静态审计支撑，需启动服务后人工复核。
